# Exit codes

> **Status: complete.** Every code below is **binding** except 5, which stays reserved and is never used. Binding: 0, 1, 2, 3, 4, 6, 7, 8, 9, 10 and 130, used by `version`, `auth`, `review`, `next`, `finalize`, `show`, `publish`, `queue`, `doctor` and `check-criteria`. From now on any change to an exit code is incompatible: it is made with `!` and a `BREAKING CHANGE:` paragraph, and from 1.0.0 it needs a new MAJOR version.

Every `agent-code-review` command ends with one of these codes. Agents and scripts branch on the code, never on the text of the message. The message on stderr explains the cause and, where possible, names the file and field involved.

The **Commands** column names the commands that return the code: `all` is every command, `none` is no command. Two tests keep this table true. A guard fails if `internal/cli` has an exit code that this table does not list, or if this table lists a binding code that no command returns. A table test runs every command through its error paths and checks that the code it returns is listed here for that command.

| Code | Status | Meaning | Commands | Typical cause |
| --- | --- | --- | --- | --- |
| 0 | Binding | Success | all | The command did what was asked. A review that finds blockers still succeeds, and so does `finalize` on a BLOCKED cascade: the verdict is in the report, not in the exit code. `doctor` succeeds when no check fails, warnings included. `check-criteria` succeeds when nothing would be ignored. |
| 1 | Binding | Unexpected error | `auth`, `review`, `next`, `finalize`, `show`, `publish`, `queue`, `doctor`, `check-criteria` | A bug or an environment problem the CLI does not classify, such as a full disk, a work directory or run log that cannot be used, packs that cannot be found or loaded (`review`, `check-criteria`; `doctor` gives 1 for packs it cannot find and 3 for a pack that is not valid), or a terminal that cannot hide the typed token: `auth login` run in a Git Bash (MSYS or Cygwin) terminal, or where the echo cannot be turned off. `doctor`: a work directory that is not writable, or any failed check that no other code covers. |
| 2 | Binding | Usage error | all | Unknown command or flag, missing argument, an invalid `--host`, or an argument where `auth login` expects the token on stdin; for `review`, a reference that is not a pull request or `owner/repo#N`, or a root on a host or platform this release does not read (only github.com is); for `next`, a `--run` that is not a run id, or a `--part` the change request does not have; for `finalize`, an argument; for `show`, a change request that is not one of the run's reports (not in the run, or skipped), a folder without `--save`, or more than one change request or folder; for `publish`, neither `--plan <comments\|issues\|both>` nor `--apply`, both, a `--plan` without one of the three, or an argument; for `queue`, a `--limit` that is not a number from 1 to 100, or an argument; for `doctor`, a `--repo` that is not `owner/repo`, or an argument; for `check-criteria`, more than one directory, or a directory that does not exist or is not a directory. The usage is printed on stderr for a malformed command line. |
| 3 | Binding | Validation error | `finalize`, `review`, `doctor`, `check-criteria` | A file does not match its schema or the work package. `finalize`: a judgement that is invalid, or missing, for any change request of the run; every problem is listed, grouped by change request with its field pointer, and nothing is written; a finding on a line the agent was not shown (outside the lines of the diff and of the code the work package carries, or on any line of a file it shows nothing of) is one of them, and so is a text over its limit (a title over 120 characters, a `why` or a `fix` over 1000, a suggestion over 50 lines, a question over 500, more than three notes or one over 200). `review`, `finalize`, `doctor` and `check-criteria`, the commands that read it: the user `config.json` is not valid. `doctor`: a pack that is not valid. `check-criteria`: anything in the repository criteria that a review would ignore, an invalid `config.json` of the repository included; this is on purpose different from `review`, where a repository criteria file that is not valid, or criteria that cannot apply, such as a rule id a pack already uses, never stop a review: they are listed under "Repository criteria ignored". |
| 4 | Binding | Head changed | `publish` | A change request has new commits since it was reviewed, in `--plan` or in `--apply`. Nothing is written for it, the other change requests are not affected, and the message lists the ones to review again. |
| 5 | Reserved | Reserved | none | Not used. A change request that edits its own criteria is still reviewed, with the target branch's criteria, and the summary notes that the edit was not applied (scenario S6 A). |
| 6 | Binding | Authentication error | `auth`, `review`, `publish`, `queue`, `doctor` | No token, an expired or refused token, or a token without the needed permission, found by `review` or `queue` on the first request that needs it (the message names the permission the platform said was missing); for `publish`, the same on a read or on a write, with what was done and what was not. For `auth`: no token available or read from stdin, a token with whitespace, git missing, or git failing to read, store or remove the token, including a git command that does not finish within 30 seconds, for example a credential helper waiting for an unlock. `doctor`: git missing, no token, a credential helper that fails, a token the platform refuses, or one without the permission to read a part of the repository named with `--repo`. |
| 7 | Binding | Platform or API error | `review`, `publish`, `queue`, `doctor` | `review`: the platform is unreachable, answers 5xx after the retries, or asks for a wait longer than the longest one accepted (60 seconds) for its rate limit; the root change request is missing or the token cannot read it (a related one is skipped as `not-found`); a change request lists more changed files than the platform returns, or holds a path with a control character and so is not reviewed. A related change request that is gone or unreadable after the cascade read it is not an error: it is skipped as `not-found` and the cascade is INCOMPLETE; a changed file whose contents cannot be read is listed as `content-unavailable`. `publish`: the same kinds of failure, on a read of `--plan` (no plan is written) or on a write of `--apply`, which stops at the first one and prints what was done and what was not; `--apply` again does what is left. `queue`: the same kinds of failure on its one search. `doctor`: the platform is unreachable or answers with an error, or the repository named with `--repo` is not there or cannot be seen by the token. |
| 8 | Binding | Invalid state | `next`, `finalize`, `show`, `publish` | `next`: there is no run, or none that is not published; the run is not in phase `collected` (it was not finished, or it is already judged); a work package is missing or damaged; or the state file has an unknown version or is damaged. `finalize`: the run is not in phase `collected`, so it is already finalized or its review did not finish (to change a judgement after `finalize`, run `review` again). `show`: the run is not finalized yet, or its findings cannot be read. `publish --plan`: the run is not finalized or planned. `publish --apply`: the run is not planned, or a plan is missing, is not valid, or has a hash other than the one in `state.json`; nothing is written. |
| 9 | Binding | Path not allowed | `show` | `show --save`: the folder for the report contains `..`, is inside a git work tree, or cannot be written. Nothing is saved. |
| 10 | Binding | Unsafe credential storage | `auth`, `doctor` | `auth login` refuses to store the token: git has no credential helper, so nothing would be stored, or `store` is among the helpers, which writes it in plain text on disk. The message says what to configure. `doctor` reports the same condition as a failed check, unless the token comes from `ACR_GITHUB_TOKEN`: then nothing is stored and it is only a warning. |
| 130 | Binding | Interrupted | `auth` | Ctrl+C or a termination request while `auth login` reads the token; the terminal echo is restored first. 130 is the shell convention for SIGINT, outside the result codes above. |

`doctor` ends with 0 when no check fails. Otherwise its code is the first of 6, 10, 7, 3 and 1 that one of its failed checks has: a missing token or git before unsafe storage, before an unreachable platform, before an invalid configuration or pack, before anything else.

Rules:

- Codes are stable once released. A new condition gets a new code; an existing code never changes its meaning.
- The CLI never prints a token, also not in error messages.
- Code 1 always means something the CLI should classify better: report it.
- Code 5 is reserved and never used.
